# Commit Guidelines

Use commit messages that describe a real change to the design or its verification.

Examples:

- `Add 2:1 mux RTL implementation`
- `Add exhaustive mux testbench`
- `Fix mux select priority bug`
- `Document reset corner-case verification`

Keep RTL, testbench, and documentation changes understandable. Avoid empty commits, meaningless edits, and splitting one trivial change into multiple commits. Record simulation results only after running the stated commands.
